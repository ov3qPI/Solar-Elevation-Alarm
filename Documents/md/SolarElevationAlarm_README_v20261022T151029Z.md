## Existing v20261022T031609Z user interface
The main page shows compact GPS, background refresh, ephemeris and exact-alarm status. Alarms appear as compact red-outlined black cards, permanently ordered from the lowest ascending solar elevation up to the highest ascending, then highest descending down to lowest descending. Disabled events remain in that ordering. `Both` events are sorted according to the direction of their next scheduled crossing, persisted in SQLite as `next_direction`; an older `Both` event from v20261022T025042Z may initially retain the ascending default until it is next rearmed. Equal-angle events are sorted by numeric event ID.
Each card contains the event name, original decimal angle, crossing direction, selected audio filename, state and local next scheduled time. `EDIT` opens the existing editor; `START` manually starts playback regardless of whether the event is armed; `ARM` or `DISARM` updates the enabled state and the Android exact alarm without deleting the event; `INFO` opens a dedicated event diagnostics page with `COPY EVENT DIAGNOSTICS`. Disarming never interrupts audio currently playing. A scheduled alarm can interrupt playback; `STOP PLAYBACK` stops playback explicitly. `STOP PLAYBACK` appears on the main screen only while a playback instance is preparing or playing, as reported by the playback service.
`DIAGNOSTICS` opens a separate screen with a `COPY DIAGNOSTICS` button. Clipboard reports are plain text and include UTC report timestamp, APK version, device SDK, ephemeris version and recorded hash, decoder version, location provider/coordinates/fix timestamp/accuracy, background GPS status/last attempt/last fresh fix, exact-alarm permission, media volume, playback state, event angles and directions, enabled status, local and UTC next trigger times, scheduling generation, filenames, document URIs and last playback outcome. The report is a snapshot at the moment the screen opens, not a live updating log. Copied diagnostics include coordinates and selected file URIs; share them intentionally.
The event editor retains blank initial name/angle fields, the 350 ms debounced crossing preview displayed only as a local ISO date-time or `Never occurs` / `Unavailable`, and `Choose audio file`. No ephemeris, GPS or WavPack decoding algorithm is changed by this version.

## v20261022T151029Z reliability fix
Scheduled alarms have priority over manual auditions and other active playback. When an alarm fires, the current audio is stopped and replaced with that alarm audio, even for the same event. START cannot interrupt a currently active playback session. The service invalidates old decoder callbacks and audio-focus callbacks when switching, and does not stop itself between the outgoing and incoming audio. Notification Stop actions carry a playback token so a delayed action from a previous track cannot stop its replacement. The Stop button is driven by in-process service liveness and boot recovery clears persisted playback flags. The existing solar scheduler, DE440s, WavPack decoder and two-color UI are unchanged.
## Functional checks
Verify events remain after installation. Confirm ascending angles increase, descending angles decrease and a `Both` event follows its next resolved crossing direction after a recalculation. Disarm one event and check that its next alarm is absent, then arm it and check a new time is calculated. Play a WV file manually and confirm the large red `STOP PLAYBACK` control appears and disappears when playback finishes. Open `INFO` and `DIAGNOSTICS`, copy both reports, and paste into a text editor to verify content. Reopen New Event and verify the preview remains ISO-only. Confirm saved background GPS permissions persist and scheduled GPS refresh continues to be reported. Use a backup alarm until overnight wake/long-playback tests pass.
## Limitations
